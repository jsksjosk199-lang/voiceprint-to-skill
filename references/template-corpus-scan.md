# 【模板】主题相关子集扫描 + 多 agent 精读（大语料用）

> **数据边界：** 本文件是空白方法模板。真实账号身份、原文摘录、私人事件及个体统计只能填写在本地私有副本；不要回填到公开仓库。这里的例子是方法示意，不能充当真实个人案例。


> 当语料很大（几十~上百份）且产出 Skill 只服务某类主题（如"只写 AI 相关内容"）时，不能只靠文件名筛，也不能让主会话一篇篇精读。用下面流程：**内容级扫描找相关子集 → 分批 → 派多个 agent 并行精读 → 汇总成方法库。**

## 一、为什么不能只看文件名

很多相关内容标题根本不体现主题。例：讲"用 AI 工具/做 AI 视频"的集，标题可能只写产品名（Seedance/数字人/Gemini），不含"AI"二字。**只看文件名会漏掉大量真正相关语料。**

## 二、内容级扫描脚本（筛相关子集）

写脚本，对每个文件**读正文**统计主题关键词频次，而非只看文件名：

```python
import os, glob, re
# 主题关键词要"宽"，含产品名/应用类型/动作，不要只靠主题词本身
kw = ["AI","Agent","Notebook","Seedance","Gemini","数字人","视频","内容","工具","自动化", ...]
for f in glob.glob(语料目录/*.txt):
    # 读正文（去掉字幕头部元信息 标题/UP主/BV号等）
    content = open(f, encoding="utf-8").read()
    count = sum(content.count(k) for k in kw)
    if count >= 阈值:  # 如≥5 → 视为相关
        print(文件名, count)
```

产出"相关子集清单"，按相关度排序。

## 三、分批策略（决定派几个 agent）

- 把子集按"相关度/主题"分成若干批，每批 3~5 篇（每篇 3000~12000 字）。
- **每批派 1 个 general-purpose agent 精读**（并行），每个 agent 用 Read 逐字读完整篇，输出 A~G 结构化笔记（见下），存成独立 md 文件。
- 一次读不完就分多轮，别让主会话扛下全部精读。

## 四、给每个 agent 的精读任务模板

> "你是内容风格分析师。请精读以下 [N] 篇 [账号] 字幕，逐字读完，产出结构化笔记。对每篇提炼：
> A. 主题相关度判定（高/中/低）+ 主要用什么工具/方法
> B. 开头怎么钩（现象/见闻/极端假设/人物案例/反常识/靶子反驳/扎心提问/预测/成果前置）+ 原句
> C. 讲[主题]的专属话术/比喻（怎么让小白秒懂）+ 原句
> D. 真实案例与数字（注明是他自己还是学员/别人）
> E. 论证逻辑（怎么让人信服）
> F. 结尾 CTA + 原句
> G. 对[产出目的：如AI Skill获客]的启示
> 写成文件：...md。完成后 200 字内汇报。"

## 五、汇总成"主题方法库"

把各批笔记的精华汇总成该 Skill 的一个独立 reference（如 `topic-library.md` / `ai-topic-method-library.md`），包含：
- 该主题的开头钩子库
- 核心比喻/翻译层（把技术讲成人话的资产）
- 论证三板斧
- 金句库
- 主题价值主张迁移
- 避坑（该主题容易踩的坑）

## 六、精读笔记存档

各批笔记和原文证据仅存入本地私有工作区（如 private/reference-notes/），不写入公共 reference，也不自动提交。
