# 创作 Skill 的文档工程检查

本文件是针对语料蒸馏任务整理的执行检查表。其文档组织方法参考并改写自 MIT 资料 [mattpocock/skills：writing-for-agents](https://github.com/mattpocock/skills/tree/main/skills/productivity/writing-for-agents)，以及 [obra/superpowers](https://github.com/obra/superpowers)。版权与原许可保留于 [第三方声明](../THIRD-PARTY-NOTICES.md)。

## 1. 让使用路径可见

入口说明输入、目标、步骤与完成条件。每条参考链接解释何时要读，使使用者可以沿自己的分支完成任务。只有特定体裁需要的细节放入对应 reference。

## 2. 用具体输出检查完成

“分析好了”不是能核对的条件；语料清单、处理回执、规则表、来源表与试写结果可以被核对。抽样与全量分别记录，材料无法读取就写清缺口。

## 3. 根据错误选择说明形式

| 错误 | 更易检查的说明 |
|---|---|
| 输出缺关键内容 | 设置需要填写的栏位 |
| 顺序和篇章结构不对 | 列出各段目的与组织方式 |
| 某要求随场景变化 | 给出触发条件与判断方法 |
| 真实性规则被违反 | 说明边界、核查方式和替代写法 |

这些方法是编写建议，效果要通过具体任务的输出验证。

## 4. 控制维护成本

同一规则保留一个明确的维护位置。相关定义、条件和边界放在一起；删去失效的说明。创建新文件时考虑它是否有独立的使用场景，而不是按固定数量凑齐文档。

## 5. 保留出处与数据边界

不得将第三方译写宣称为全部原创。原文和账号证据放在私有工作区；公开示例使用作者自写文本并标记示意性质。不同许可的资料保留其各自声明。

## 6. 验收清单

- [ ] YAML 文件头有效，用途描述与实际步骤一致。
- [ ] 参考链接可达，每份资源有读取时机。
- [ ] 步骤都有可核对的完成条件。
- [ ] 试写确实使用了规则，真实性和来源边界得到检查。
- [ ] 用户授权和任务目标未被模板假设替代。
- [ ] 拟发布文件不含原文库、账号映射和私人资料。
